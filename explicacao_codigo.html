Documentação Técnica do Sistema

Aprenda a arquitetura, modelos, gerenciadores e o fluxo de dados do AM Orçamentos.

📁 Organização do Projeto

O sistema é modular, seguindo uma separação clara de responsabilidades baseada no padrão de arquitetura de camadas: Modelos de Domínio (Models) para descrever os dados, Controladores (Managers) para orquestrar a lógica de negócios e menus CLI, e uma Camada de Acesso a Dados (Persistence/Storage) para gravar os arquivos.

🧱 Modelos de Domínio (Models)

Os modelos representam as entidades reais do sistema. O projeto faz uso de herança de classes para reaproveitar estruturas de dados comuns.

Cliente

models/cliente.py

Representa o cliente do sistema. Contém dados de contato e o atributo arquivado para permitir a exclusão lógica em vez de física, facilitando a recuperação posterior caso seja necessário restaurar o registro. 

class Cliente:
    def __init__(self, id, nome, telefone, email):
        self.id = id
        self.nome = nome
        self.telefone = telefone
        self.email = email
        self.arquivado = False # Soft delete / Arquivamento

    def exibir_dados(self):
        status = "Arquivado" if self.arquivado else "Ativo"
        print(f"\nID: {self.id}\nNome: {self.nome}\nTelefone: {self.telefone}\nEmail: {self.email}\nStatus: {status}\n" + "-"*30)
{
    "id": 1,
    "nome": "João Silva",
    "telefone": "(84) 99999-8888",
    "email": "joao@email.com",
    "arquivado": false
}

Material

models/material.py

Utiliza herança simples. A classe pai genérica Produto armazena o nome e serve como base para Material, que adiciona o preço por metro quadrado (preco_m2), utilizado para calcular o custo total de cobertura nos orçamentos. 

class Produto:
    def __init__(self, nome):
        self.nome = nome

class Material(Produto):
    def __init__(self, nome, preco_m2):
        super().__init__(nome)
        self.preco_m2 = preco_m2

    def __str__(self):
        return f"Material: {self.nome} | Preço por m²: R$ {self.preco_m2:.2f}"
{
    "nome": "MDF Branco 15mm",
    "preco_m2": 120.0
}

Orçamento

models/orcamento.py

Herda de Cadastro (que guarda o cliente e a descrição do serviço). O modelo Orcamento estende essas propriedades adicionando dados operacionais e financeiros, como material associado, quantidade de peças, área, valor de montagem e taxa de cartão. 

class Cadastro:
    def __init__(self, cliente, descricao):
        self.cliente = cliente
        self.descricao = descricao

class Orcamento(Cadastro):
    def __init__(self, cliente, descricao, material, quantidade, area, montagem, taxa_cartao, observacao):
        super().__init__(cliente, descricao)
        self.material = material # Instância da classe Material
        self.quantidade = quantidade
        self.area = area
        self.montagem = montagem
        self.taxa_cartao = taxa_cartao
        self.observacao = observacao

Metragem

calculos.py

A classe Metragem representa as medidas de largura e comprimento de uma peça de trabalho. Aplica o encapsulamento estrito utilizando Double Underscore (__) nos atributos, tornando-os privados em Python. 

class Metragem:
    def __init__(self, descricao, largura, comprimento):
        self.__descricao = descricao     # Privado
        self.__largura = largura         # Privado
        self.__comprimento = comprimento # Privado

    def calcular_area(self):
        return self.__largura * self.__comprimento

    def __str__(self):
        return f"{self.__descricao} | {self.__largura}m x {self.__comprimento}m | Área: {self.calcular_area():.2f} m²"
{
    "descricao": "Tampo da mesa",
    "largura": 1.2,
    "comprimento": 0.8
}
⚠️
Nota de Implementação (Duplicidade no Código):
Existe um arquivo chamado models/segmento.py que redefine a classe Metragem com propriedades públicas e uma lógica CLI em SistemaMetragem. No entanto, o sistema central de orçamentos e a persistência em database.py utilizam a classe Metragem declarada em calculos.py. O arquivo models/segmento.py permaneceu isolado no repositório.

⚙️ Controladores (Managers)

Os Managers representam os controladores da aplicação. Eles fazem o intermédio entre a interface de entrada (menus de terminal) e a gravação permanente no banco de dados.

ClienteManager

OOP

Implementado como Classe. Controla o carregamento de clientes do banco, separando-os entre ativos e arquivados.

__init__()
Carrega os clientes do banco e define o próximo ID disponível varrendo os maiores registros.
cadastrar_cliente()
Solicita os dados pelo terminal, gera uma instância e dispara o salvamento.
arquivar_cliente() / restaurar_cliente()
Implementa a lógica de remoção suave, movendo objetos entre as listas "ativas" e "arquivadas".

MaterialManager

Funcional

Implementado de forma procedimental com funções soltas no módulo. Facilita o cadastro rápido de insumos.

adicionar_material()
Lê nome e preço/m², cria o objeto e o adiciona à lista global, chamando o banco em seguida.
listar_materiais()
Lista todos os materiais cadastrados exibindo seus índices numéricos para escolha.
editar_material() / excluir_material()
Localiza o material com base no índice da listagem e aplica a exclusão ou alteração.

OrcamentoManager

Funcional

Orquestra orçamentos. Fornece o motor de cálculo financeiro completo do projeto.

criar_orcamento()
Permite associar o orçamento a um material carregado em memória via seletor numérico.
calcular_total_orcamento()
Calcula os totais utilizando a seguinte fórmula financeira:
C_material = Preco_m2 * Area
Subtotal = C_material + Montagem
Taxa = Subtotal * (Taxa_cartao / 100)
Total = Subtotal + Taxa

SegmentoManager

Funcional

Controla a medição pontual de áreas físicas. Ideal para o levantamento de chapas ou revestimentos necessários.

adicionar_medida()
Instancia Metragem com a descrição e largura/comprimento fornecidos e salva no banco.
calcular_total()
Percorre a lista de metragens cadastradas, somando a área calculada de cada item em m².

💾 Persistência de Dados & JSON

A persistência de dados é estruturada em duas subcamadas principais para separar a conversão de tipos (Serialização) da escrita física em disco (Storage Engine).

1. O Adaptador (database.py)

database.py

O JSON suporta apenas tipos primitivos (texto, inteiros, decimais, listas e dicionários). O arquivo database.py traduz os objetos do sistema (como instâncias de Cliente) para dicionários e vice-versa.

💡
Resolução de Referências: Ao carregar orçamentos, o banco guarda apenas o nome do material (chave estrangeira). A função _dict_para_orcamento realiza uma busca linear na lista de materiais ativos para associar novamente o objeto Material correto em memória.
🔒
Desvio de Atributo Privado (Name Mangling): Para salvar a Metragem de calculos.py, o adaptador contorna os campos privados usando a sintaxe interna do Python: medida._Metragem__descricao.

2. O Motor de Escrita (storage.py)

storage.py

É um motor de gravação agnóstico. Ele não importa nenhuma classe do sistema, apenas lê e grava strings/estruturas básicas em arquivos, garantindo segurança operacional absoluta:

  • Backups Automáticos: Antes de gravar, cria uma cópia do arquivo atual na pasta backups/ usando o formato de data/hora arquivo.json.YYYYMMDD_HHMMSS.bak, mantendo no máximo 5 backups.
  • Gravação Atômica: Grava primeiro em um arquivo temporário .tmp. Após a escrita correta, substitui o original usando os.replace(). Se faltar energia ou o programa cair no meio, o arquivo antigo nunca é quebrado.
  • Auto-recuperação (Self-Healing): Se o arquivo original corromper por interferência externa, o sistema detecta a falha, move-o para um arquivo .CORROMPIDO, busca o backup válido mais recente e o restaura.

Por que gravação atômica importa?
Se o Python tentasse escrever diretamente no arquivo clientes.json e o computador sofresse uma queda de energia no exato milissegundo da escrita, o arquivo ficaria preenchido pela metade (JSON corrompido e ilegível). Gravando no .tmp e rodando os.replace, o sistema operacional garante que a alteração seja instantânea: ou o arquivo é gravado 100% ou se mantém intacto na versão anterior.
